Help

For Raha 0.3.3. If your problem is not here, write to the person who makes Raha.

Raha will not open

macOS says it cannot check Raha for malicious software

The 0.3.3 files are not signed with a developer certificate, so macOS stops the first launch of every copy and asks you to confirm it.

  • macOS 15 and later: try to open Raha once. Soon after, open System Settings → Privacy & Security, scroll down, and click Open Anyway. The button is there for about an hour after the attempt; macOS then asks for your password.
  • macOS 13 and 14: in Applications, right-click Raha and choose Open, then Open again.

After that Raha opens as usual. A new version is a new copy, so macOS may ask again after an update.

macOS says Raha “needs to be updated”

This is the wrong file for the Mac, not an old version. There are two Mac files, and the Apple Silicon one does not open on an Intel Mac. In the Apple menu, About This Mac shows “Chip Apple M…” on an Apple Silicon Mac and “Processor Intel…” on an Intel Mac. The download list has both files.

Windows says “Windows protected your PC”

The installer is not signed, and SmartScreen shows this for unsigned installers. Click More info, then Run anyway. It may ask again for a new installer you download. If Smart App Control is on in Windows 11, it may block Raha with no Run anyway button.

Linux: nothing happens when the AppImage is opened

A downloaded file is not allowed to run until you say so. In a terminal, in the folder with the file:

chmod +x Raha-0.3.3.AppImage
./Raha-0.3.3.AppImage

If it says FUSE is missing, install it: on Ubuntu 24.04 sudo apt install libfuse2t64, on 22.04 sudo apt install libfuse2.

Linux: the .deb installed but Raha does not start

The 0.3.1 .deb did not start on a system without the ALSA sound library or libgbm1, for example a stock Ubuntu 24.04. The 0.3.3 .deb asks for both. Install it with apt, which fetches them:

sudo apt install ./raha-browser_0.3.3_amd64.deb

If Raha still does not open, report it.

Raha did not update

First see which version you have: open Settings (the gear, or ⌘ ,; Ctrl , on Windows and Linux) and scroll to the bottom. Under About it says “Raha 0.3.3”, or an older number.

On macOS

In 0.3.3, Raha on macOS does not install updates, even with “Install security updates automatically” on. It shows a short notice, “Raha 0.3.3 is available — download it from GitHub Releases”, and nothing more: the updater on macOS installs only into signed apps, and 0.3.3 is not signed. The new version is installed by hand, and your tabs stay: steps for macOS.

On Windows, and on Linux with the AppImage

Raha downloads the new version in the background and shows “Raha 0.3.3 downloaded — installs when you quit”. The update happens when Raha quits, so quit it and open it again.

If the version is still old, look in Settings under Privacy: “Install security updates automatically” must be on, and the computer must reach GitHub. Raha checks about 30 seconds after it starts and every four hours. Or install the new file yourself: steps.

On Linux with the .deb

Update a .deb by installing the new one with apt: steps.

Tabs or settings look wrong after a start

Raha keeps your tabs, settings and history in three files. If it cannot use one of them at start, it copies that file aside before saving anything, starts without it, and says so, naming the copy it kept in the profile folder (where it is):

Raha could not use one of its files and kept a copy in your profile folder: state.json.corrupt-1762862400000

The name tells which file it was: state.json holds tabs and folders, settings.json the settings, history.json the history. Without the file, Raha starts with no tabs, with default settings, or with empty history. A copy ending in .corrupt- and a number is a file Raha could not read. One ending in .newer- was written by a later version of Raha than the one now running.

Three more notices can follow:

… is copied as it was and may hold what the old file held, such as open pages and typed text. You can delete it.

Raha could not clean this copy, because it could not read it. Deleting it is your choice. It is also the only record of those tabs, so keep it if you want the problem looked at.

Raha removed old copies it had kept for more than two weeks: …

Raha removes a copy only when it is older than two weeks and three newer copies of the same file exist.

Raha could not read … or keep a copy of it, so it will not save over it. Changes to it are not saved.

Raha could not make the copy, so it leaves the file as it is. Until this is solved, what you change in that file’s area (tabs, settings or history) is lost when Raha quits.

What to do. Quit Raha, and leave the files in the profile folder as they are. Then write by email and give the words of the notice. These files list the pages you had open and visited, so do not attach them to a public issue.

One change after a restart is by design: pages reached with Back or Forward load fresh, without their scroll position or typed text (Status of 0.3.3).

A tab went to sleep, or a page loads again when clicked

Raha limits how many tabs run at once: six by default. When a seventh starts, the background tab used least recently goes to sleep, and a notice says why, for example “Live-tab cap reached: “…” went to sleep”. A sleeping tab’s process is closed and its memory goes back to the computer. A click loads its page again. The address, the title, and Back and Forward are kept. Scroll position and unsent form text are kept too, unless that setting is turned off. Anything else on the page starts over, such as the place in a video.

After a restart every tab is asleep, so the window shows thumbnails until you click one.

To change this:

  • Let more tabs run. Settings → Max live tabs, from 1 to 16.
  • Keep one tab awake. Click the pin in the toolbar (“Keep alive”), or press ⌘ ⇧ K (Ctrl Shift K). A pinned tab does not sleep on its own, unless you gave it a memory limit and it passes it.
  • Keep a site awake. Settings → Domain rules: enter the site, for example *.example.com, tick keep alive, and add the rule.

A tab that is playing sound is not put to sleep.

A background tab left idle for two minutes is frozen: it is paused, keeps its memory and its page, and continues on a click without loading again. “Freeze background tabs after” in Settings changes the time or turns this off.

A site does not work

Parts of the page are missing or a button does nothing

Raha blocks known ads and trackers, and a site can depend on one. Click the shield in the address bar to turn blocking off for that site; click it again to turn it back on.

A sign-in or a “verify you are human” page goes in circles

Right-click the page and choose Clear Cookies & Data for This Site. Raha asks first, because this signs you out of that site. Other sites are not touched.

The site asks for a passkey or a security key

0.3.3 supports neither passkeys nor USB security keys. Choose another way to sign in if the site offers one, such as a password or a code.

A chat, call, video or upload stopped

The tab was probably frozen while in the background, and its connection did not come back. Reload the page (⌘ R, Ctrl R). A pinned tab is not frozen automatically, and neither is a tab playing sound (how to pin).

The camera, microphone, location or notifications do not work

A site must ask in Raha’s own prompt. If you chose Never for this site, remove that answer in Settings → Site permissions, and the site can ask again. Screen sharing is not available in 0.3.3: Raha refuses it.

If none of this helps, report it and name the site.

Your data

Where it is

Everything Raha keeps about your browsing is in one folder on your computer, named Raha. Raha has no account and no sync, so there is no other copy.

macOS
~/Library/Application Support/Raha
In Finder: Go → Go to Folder…, and paste the path.
Windows
%APPDATA%\Raha
Paste it into the address bar of File Explorer.
Linux
~/.config/Raha
The .config folder is hidden in most file managers.

Inside it, the profile folder is Raha’s own: state.json (tabs and folders), settings.json, history.json, and thumbs (a picture of each tab). The rest of the Raha folder is kept by Chromium: cookies, sign-ins and what sites have stored. Downloads are ordinary files, wherever you saved them.

Backing it up

Quit Raha and copy the whole Raha folder. To go back to that copy, quit Raha and put the folder back in the same place. Cookies are encrypted with a key that the operating system holds, so sign-ins may not come along to another computer or another account.

Taking it to another browser

0.3.3 has no export. It cannot write your tabs, folders or history as a file that another browser reads. state.json and history.json are plain text: they hold the address and title of each tab and of each page in the history, and any text editor opens them. Raha has no password manager, so it holds no saved passwords to take along.

Removing Raha

Removing the app leaves the Raha folder on every system. Deleting that folder removes your tabs, folders, settings, history, cookies and sign-ins, and it cannot be undone.

  • macOS: quit Raha and move it from Applications to the Trash. Then delete ~/Library/Application Support/Raha.
  • Windows: in Windows Settings, open Apps, find Raha and choose Uninstall. Then delete %APPDATA%\Raha. A downloaded update may also be left in %LOCALAPPDATA%\raha-browser-updater.
  • Linux, AppImage: delete the AppImage file, then ~/.config/Raha. A downloaded update may also be left in ~/.cache/raha-browser-updater.
  • Linux, .deb: sudo apt remove raha-browser, then delete ~/.config/Raha.

To keep Raha and start it fresh, quit it and delete the Raha folder. Everything named above is removed, and it cannot be undone. To keep a copy, move the folder somewhere else instead.

Questions people ask first

Is it free?

Yes. There is no paid version and no account. The project is supported by donations.

Who makes it?

Amir Basareh, with AI coding assistants (how).

Is it ready for everyday use?

0.3.3 is an early version. It suits people who keep many tabs open and want to choose how many run. Four limits matter most: the files are not signed, so the first launch asks you to confirm; it does not warn about dangerous sites or downloads; third-party cookies are not blocked (blocking is built for 1.0); on macOS, updates are installed by hand. Each limit and its plan: Status of 0.3.3.

Does it have extensions, sync, a password manager or a phone version?

No, none of the four.

What does it send?

No telemetry. Apart from the pages you open, it makes three kinds of request on its own, each listed under Privacy.

When does 1.0 come out?

It has no date. What is built so far, and how to hear of the release.

Still stuck, or found a problem

Raha is made by one person, who reads the reports himself. A reply can take several days, sometimes longer.

  • Bugs and ideas: GitHub issues. Issues are public: anyone can read them, so leave out passwords, private addresses and personal details.
  • Questions: Discussions, also public.
  • Something private, or no GitHub account: basareh@duck.com.
  • Security problems: GitHub’s private form, or email with a subject starting [raha security] (SECURITY.md).

A report is easiest to act on with four things: the Raha version (Settings, at the bottom, under About), your system and its version, what you did, and what you saw, with the exact words of any notice.
